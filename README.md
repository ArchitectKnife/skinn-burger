# BURGER SKIN

Платформа открытия кейсов CS2: каталог кейсов и скинов, открытие с Provably Fair, инвентарь, апгрейд, контракты, Case Battle, 7 мини-игр (Crash, Double, Jackpot, Coinflip, Roulette, Mines, Towers), BURGER PASS на 100 уровней, бонусы и задания, друзья, поддержка, финансовый раздел и админ-панель с ролями.

## Требования

- Node.js 24.7 или новее. Используются встроенные `node:sqlite`, `crypto.argon2` и запуск TypeScript без сборки.
- npm. Для работы сайта сторонние пакеты не нужны. `typescript` и `@types/node` нужны только для проверки типов.
- Для импорта большого каталога и цен нужен доступ в интернет.

## Быстрый старт

```bash
npm install
cp .env.example .env          # Windows: copy .env.example .env
npm run seed                  # один раз: база, стартовые кейсы, задания, сезон BURGER PASS
npm run import:catalog -- --download-images   # тысячи скинов CS2 с изображениями (нужен интернет)
npm run import:prices                         # рыночные цены Skinport (нужен интернет)
npm run create-owner          # первый владелец, см. ниже
npm start
```

Сайт откроется на `localhost:3000` (порт задаётся в `PORT`). Для разработки: `npm run dev` (перезапуск при изменениях).

Все команды автоматически читают `.env`, если он есть.

## Первый владелец (OWNER)

Публичной регистрации администраторов нет, пароль владельца в коде не хранится.

1. Заполните в `.env`:
   ```
   OWNER_LOGIN=boss
   OWNER_EMAIL=boss@example.com
   OWNER_PASSWORD=надёжный-пароль-123
   ```
   Пароль: от 8 до 128 символов, обязательно буквы и цифры. В базу записывается только хеш Argon2id.
2. Выполните `npm run create-owner`.
3. Удалите `OWNER_PASSWORD` из `.env`.
4. Войдите на `/login` и откройте `/admin`.

Другие варианты:

- `npm run create-owner -- --promote`: сделать владельцем уже зарегистрированный аккаунт `OWNER_LOGIN`.
- `npm run create-owner -- --reset-password`: задать владельцу новый пароль из `OWNER_PASSWORD`.
- Windows PowerShell без `.env`: `$env:OWNER_LOGIN="boss"; $env:OWNER_EMAIL="boss@example.com"; $env:OWNER_PASSWORD="..."; npm run create-owner`.

## Роли

| Роль | Доступ |
|---|---|
| OWNER | всё, включая роли, системные настройки и резервные копии |
| ADMIN | пользователи, кейсы, скины, игры, бонусы, BURGER PASS, финансы, новости |
| MODERATOR | пользователи (блокировки и ограничения), новости, подозрительная активность |
| SUPPORT | обращения в поддержку |
| USER | игрок |

Права проверяются на сервере при каждом запросе к `/api/admin/*`. Скрытие кнопок в интерфейсе только дублирует эту проверку. Все действия сотрудников пишутся в журнал аудита с цепочкой хешей. Целостность проверяется в разделе «Журнал аудита».

## Каталог скинов и кейсов

Источник каталога: открытый ByMykel/CSGO-API (MIT). Это данные из файлов игры, изображения берутся с CDN Steam. Источник цен: публичный API Skinport.

```bash
npm run import:catalog                         # скачать skins.json и crates.json и импортировать
npm run import:catalog -- --download-images    # плюс сохранить картинки локально в public/img/items/ext
npm run import:catalog -- --file skins.json --crates crates.json   # импорт из локальных файлов (JSON или CSV)
npm run import:catalog -- --no-cases           # не перестраивать кейсы
npm run import:prices                          # цены Skinport в RUB
npm run import:prices -- --currency USD        # другая валюта
npm run import:prices -- --file prices.csv --source steam-market   # свой файл цен
```

Кейсы собираются только из предметов, у которых есть и изображение, и цена. Поэтому после каталога обязательно запустите `import:prices`: тематические кейсы (ножи, перчатки, по оружию, по редкости, коллекции) будут созданы и пересчитаны автоматически.

Формат собственного файла цен: JSON-массив или CSV с колонками `market_hash_name` и `price` (также подходят `suggested_price`, `median_price`, `min_price`). Импорт каталога и цен доступен и из админ-панели: раздел «Импорт и цены».

Валюта сайта — рубли (₽). Балансы и цены хранятся в копейках; при переходе с обозначения BC числовые значения не изменялись и никакой конвертации не выполнялось.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `PORT`, `HOST` | адрес сервера (по умолчанию 3000 и 0.0.0.0) |
| `PUBLIC_URL` | публичный адрес сайта. Нужен для Steam OpenID, писем и реферальных ссылок |
| `COOKIE_SECURE=1` | флаг Secure для cookie, обязателен при HTTPS |
| `TRUST_PROXY=1` | доверять X-Forwarded-For, только за своим reverse proxy |
| `RATE_IP_LIMIT` | общий лимит запросов с одного IP |
| `STEAM_API_KEY` | ключ Steam Web API для имени и аватара при входе через Steam. Сам вход через Steam OpenID работает и без ключа |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | почта для восстановления пароля. Без SMTP восстановление честно отключено |
| `OWNER_LOGIN`, `OWNER_EMAIL`, `OWNER_PASSWORD` | только для `npm run create-owner` |
| `DATA_DIR`, `DB_FILE` | где хранятся база, загрузки и резервные копии (по умолчанию `./data`) |
| `PAYMENT_<ID>_ENABLED=1` | включение платёжного провайдера, см. ниже |

## Пополнение и вывод

Интерфейс баланса, заявок, статусов и уведомлений готов. Обработка заявок в админке защищена от повторного решения. Реальные платежи и вывод предметов отключены: сервер отвечает 503, интерфейс честно сообщает о недоступности, фиктивных подтверждений нет.

Чтобы подключить провайдера после юридической проверки, лицензирования и договора:

1. Создайте `src/lib/providers/<id>.ts` по интерфейсу из `src/lib/payments.ts` и зарегистрируйте его через `registerProvider`.
2. Добавьте ключи провайдера в `.env` и `PAYMENT_<ID>_ENABLED=1`.
3. Включите функции «Пополнение» и «Вывод» в админке: «Настройки», затем «Функции».

## Безопасность

- Пароли: Argon2id. Сессии: случайный токен в HttpOnly cookie, в базе хранится только его хеш.
- CSRF: double-submit токен и проверка Origin. Плюс CSP, X-Frame-Options и прочие защитные заголовки.
- Rate limiting на вход, регистрацию, восстановление пароля, ставки, сообщения и финансы.
- Все SQL-запросы параметризованы. Входные данные валидируются на сервере.
- Денежные операции атомарны (транзакции SQLite), баланс не может уйти в минус. Каждая операция пишется в журнал баланса.
- `Idempotency-Key` защищает от повторного выполнения запроса. Статусы предметов защищают от повторной продажи и гонок.
- Результаты определяются только на сервере: HMAC-SHA256(server seed, client seed:nonce:cursor). Хеш server seed показывается заранее, после смены seed его можно проверить на странице `/fair`.
- Шансы кейса фиксируются в момент открытия. Скрытого изменения шансов нет.
- Секреты хранятся только в переменных окружения.

## Резервное копирование

- `npm run backup` создаёт атомарную копию базы (`VACUUM INTO`) в `data/backups/`. То же самое можно сделать в админке: раздел «Резервные копии».
- Восстановление:
  1. Остановите сервер.
  2. Сохраните текущий `data/burger.sqlite` на всякий случай.
  3. Скопируйте нужный файл из `data/backups/` на место `data/burger.sqlite`.
  4. Удалите `data/burger.sqlite-wal` и `data/burger.sqlite-shm`, если они есть.
  5. Запустите сервер.
- Загруженные файлы (аватары, обложки, вложения) лежат в `data/uploads/`. Копируйте эту папку вместе с базой.

## Про стек

Предпочтительный стек (Next.js, Prisma, PostgreSQL) в среде разработки был недоступен: не было доступа к интернету для установки пакетов. Поэтому проект написан на TypeScript поверх встроенных возможностей Node.js 24: SQLite, Argon2id, SSE. Ему не нужны внешние зависимости, и он запускается одной командой.

Бизнес-логика отделена от транспорта: `src/lib/*` и обработчики в `src/routes/*`. Схема базы описана миграциями в `src/lib/db.ts`. Для перехода на PostgreSQL и Prisma схему можно перенести в `schema.prisma` один в один, а функции `one`, `all`, `run` и `tx` заменить на клиент Prisma.

Для продакшена разместите сервер за reverse proxy с HTTPS (nginx или Caddy) и задайте `PUBLIC_URL`, `COOKIE_SECURE=1` и `TRUST_PROXY=1`. Буферизацию для `/api/live` нужно отключить, заголовок для этого уже выставлен.


## Версия 2: доработки

- **Ширина и шапка.** Контейнер до 1600 px, сетка кейсов 6/5/4/3/2 в ряд в зависимости от экрана. Пункты меню, которым не хватает места, автоматически уходят в меню «Ещё» (без наложений на любой ширине); ниже 1100 px — бургер-меню и нижняя панель.
- **Валюта — рубли.** Все суммы показываются в формате `1 250,00 ₽`. Значения в базе хранятся в копейках и не конвертировались: 1 старая единица = 1 ₽.
- **Звуки.** Кейсы: клик, старт, тики прокрутки, замедление, остановка, редкий дроп, нож/перчатки, продажа. Апгрейдер: выбор, множитель, запуск, вращение, успех, неудача, редкий предмет. Настройки: вкл/выкл, общая громкость, эффекты, апгрейдер. Сохраняются в браузере и в профиле. До первого действия пользователя звук не играет.
- **Апгрейдер.** Шанс считает только сервер: `min(макс. шанс, RTP × (ставка / цель) ^ кривая)`. Пресеты ×2/×3/×5/×10 и свой множитель (от минимума до максимума из настроек). Защита: ключ идемпотентности, проверка цены (409 price_changed), атомарное списание предметов (409 item_unavailable), запрет дублей, результат через Provably Fair.
- **Обложки кейсов.** Собираются из реальных изображений предметов кейса (до 3 шт.) или задаются картинкой. Управление — «Админ-панель → Обложки».
- **Новые кейсы:** `npm run seed:cases` (11 кейсов, повторный запуск ничего не дублирует).
- **Премиальный каталог:** `npm run import:premium` (нужен интернет; список из 362 настоящих ножей, перчаток и дорогих скинов в `scripts/premium-wishlist.json`), затем `npm run import:prices` для цен из проверенного источника.
- **Админ-панель:** звук (`/admin/sound`), апгрейдер (`/admin/upgrader`), обложки (`/admin/covers`), список недостающих скинов (`/admin/wishlist`), плюс прежние разделы каталога, кейсов, импорта, цен и аудита.


## Версия 3: расширенный каталог

Добавлено 110 новых скинов (39 ножей, 40 перчаток, 19 винтовок и снайперских винтовок, 8 пистолетов, 4 SMG), 152 проверенные цены и 15 новых кейсов.

- Источник данных: `scripts/steam-market-snapshot.json`, снимок Steam Community Market от 09.11.2026 (минимальная цена продажи, название, редкость, изображение).
- Цены переведены в рубли по курсу ЦБ РФ 82,1386 ₽ за 1 USD от 07.11.2026. Курс и дата записаны в снимке и в источнике каждой цены.
- Изображения: официальный CDN Steam (`community.akamai.steamstatic.com`), отдаются через серверный прокси `/img/ext/` с кэшем в `data/imgcache`.
- Предмет добавляется только при наличии цены обычной версии. Диапазон float ограничен качествами, для которых есть цена, поэтому из кейсов выпадают только качества с реальной ценой. StatTrak и Souvenir включаются, только если их цена есть для всех этих качеств.
- Группы, для которых в снимке есть только цена StatTrak или Souvenir, пропускаются (71 группа).
- Предметы, которые уже есть в каталоге из других источников, не изменяются.
- Ограничение источника: Steam Market не продаёт лоты дороже примерно 2000 USD, поэтому Dragon Lore, Howl, Karambit Fade и подобные предметы этим способом оценить нельзя. Для них нужен другой проверенный источник цен (импорт через `npm run import:prices`).

Применение на своей базе (ничего не удаляется, повторный запуск безопасен):

```
npm run backup
npm run import:steam
npm run seed:cases3
```

Шансы обратно пропорциональны цене предмета, цена кейса считается автоматически. Состав, шансы, цену и обложку можно менять в админ-панели.
